# スキルと学習のメトリクス

**学び続けるチームは、サービスを健全に保つ。したがって、持続可能なペースの中で学習の時間を守り、スキルが広がり使われているかを測り、証明書やコースの件数を、能力の証明ではなく、手がかりとして扱う。**

## 概要と動機

サービスは、それを作った人々より長く生き続け、その下の技術は絶えず変わります。チームがついていく能力は、何を知り、どれだけ速く学ぶかに依存します。アジャイル宣言の原則には、技術的な卓越性への継続的な注意と、より効果的になる方法についての定期的な振り返りが含まれます。ITILの継続的改善とナレッジマネジメントのプラクティスは、組織の側から同じ必要を記述します。スキルと学習の測定値は、サービスを運営し変更する能力が存在するか、不在に耐えられるほど広く広がっているか、組織が人々に成長する時間と支援を与えているかを問います。

学習は数えやすく、うまく測るのが難しいものです。研修の時間、コースの修了、証明書は目に見えますが、そのどれも、誰かが仕事で新しいことをできるかを示しません。[専門職の認証（professional certification）](https://en.wikipedia.org/wiki/Professional_certification)は、ある時点で人が評価基準を満たしたことを示します。特にITILやアジャイルの基礎のような規制対象の役割や入口では有用な証拠ですが、その人の現在のスキルや判断の測定値ではありません。したがって、このトピックは、使われている能力の測定値に頼ります。誰が何を運用し変更できるか、新しい人がどれだけ速く役立つようになるか、学びが仕事に現れるか。

いくつかの考え方がアプローチを形作ります。

- **価値ある知識の多くは[暗黙知（tacit）](https://en.wikipedia.org/wiki/Tacit_knowledge)である。** マイケル・ポランニーは、私たちが語れる以上のことを知っていると観察した。複雑なサービスの運用には、書き下しにくい判断が伴い、それは主に他者と並んで働くことを通じて広がる。文書は役立つが、[ペアプログラミング（pair programming）](https://en.wikipedia.org/wiki/Pair_programming)、シャドーイング、レビューのような共有された実践の代わりにはならない。
- **幅と深さの両方が重要である。** [T字型スキル（T-shaped skills）](https://en.wikipedia.org/wiki/T-shaped_skills)は、一つの領域に深さを持ち、他に実用的な幅を持つ人を記述する。T字型の人々のチームは、不在をカバーし、境界をまたいで協働できる。[クロストレーニング（cross-training）](https://en.wikipedia.org/wiki/Cross-training_(business))は、その幅を意図して築く。
- **学びは社会的である。** [実践コミュニティ（community of practice）](https://en.wikipedia.org/wiki/Community_of_practice)は、技能を共有し、互いから学ぶ人々のグループである。[メンターシップ（mentorship）](https://en.wikipedia.org/wiki/Mentorship)は、経験の浅い人をより経験豊富な人と組にする。どちらもチームの境界をまたいで知識を広げる。
- **組織は学べる。** ピーター・センゲが広めた用語である[学習する組織（learning organization）](https://en.wikipedia.org/wiki/Learning_organization)は、人々の学びを通じて絶えず自らを変革する。インシデントの非難なきレビューのような実践が、組織が経験から学ぶ方法である（トピック 4.2「ポストモーテムと学習のメトリクス」を参照）。

学習の測定値には、独自の歪みがあります。研修の予算は、誰も適用しないコースに使われます。学習の時間は約束され、そしてインシデントに消費されます。個人はスキルの棚卸しで順位付けされ、知らないことを隠すようになります。[グッドハートの法則（Goodhart's law）](https://en.wikipedia.org/wiki/Goodhart%27s_law)からの防護柵が当てはまります。学習時間が目標になると、人々はセッションに出席し、証明書が目標になると、人々はそれを集めます（トピック 1.2「グッドハートの法則とメトリクスの心理学」を参照）。

持続可能なペースもここでは重要です。夜や週末に押し込まれた学習は、人々へのコストであり、健全な組織のしるしではありません。以下の測定値は、勤務週内の守られた時間を見ます。

## 主要な原則

- **コースへの出席ではなく、使われている能力を測る。** 人々ができること、していることを見る。
- **持続可能なペースの中で学習時間を守る。** 学習を無給の追加にしない。
- **意図して知識を広げる。** 知識の単一の点は、サービスへのリスクであり、その人への負担である。
- **証明書を、証明ではなく証拠として扱う。** 一部の役割には重要だが、現在のスキルについてはほとんど語らない。
- **仕事から学ぶ。** インシデント、レビュー、ペアリングは、ほとんどのコースより多くを教える。
- **スキルのデータをチームのレベルに保つ。** 個人を棚卸しで順位付けしてはならない。
- **人々に自分の学びを形作らせる。** 意欲のある人々は、時間と支援を与えられれば、よく選ぶ。

## 推奨事項

### 時間を守り、現実のものにする

**1. 学習時間をキャパシティに計画する。** 毎週の定期的なブロックのように、各チームのキャパシティの一部を学習のために確保し、キャパシティ計画に書き込みます。全員がデリバリーに全稼働で働くと仮定する計画には、学ぶ余地がありません。実際に使われた割合を追跡し、不足する理由を見ます。インシデント、締め切り、文化。これは、計画と作業負荷のトピックに結び付きます（トピック 2.5「デリバリー予測と計画のメトリクス」を参照）。

**2. 人々に、指針とともに選ばせる。** 意欲のある人々は、自分が学ぶ必要のあるものを知っています。予算と時間、選択肢のメニュー、チームの必要についての対話を提供します。学んだことをチームと共有するよう人々に求めます。それが価値を倍にします。仕事に関係のない義務的な学習は避けます。

**3. 学習を仕事の一部にする。** ペアリング、ローテーション、シャドーイング、コードレビュー、社内の発表、非難なきインシデントのレビューは、実際の問題の文脈で教えます。キャパシティ計画で、それらを学習として数えます。デリバリーしながら学ぶチームは、デリバリーから離れる時間が少なくて済みます。

### 知識を広げる

**4. 重要なタスクと、それを行ったことのある人をマップする。** 確実に行われなければならないタスクを列挙します。データベースの復旧、鍵のローテーション、重大インシデントの対応、リスクのある変更のデプロイ。それぞれについて、最近実行した人を記録します。地図は、知識の単一の点を示します。自己評価に基づくスキルの棚卸しは現実から漂流するので、最近の仕事の証拠で検証します（トピック 9.3「協働と引き継ぎのメトリクス」を参照）。

**5. 意図してクロストレーニングする。** すべての重要なタスクに、最近それを行った人が少なくとも二人いるよう、ペアリングとローテーションを計画します。可能なところでは訓練とゲームデーで練習します。狙いは耐障害性と持続可能なオンコールで、助けられる唯一の人であることから専門家を解放します。

**6. 実践コミュニティとメンタリングを支える。** 信頼性、テスト、セキュリティ、サービスマネジメントなどの技能を中心にした任意のグループを奨励し、そのための時間を作ります。チーム横断のメンタリングを提供します。参加を、チームのレベルで軽く測り、コミュニティが何を生み出したかを尋ねます。共有された実践、ツール、教訓。

### うまくオンボーディングする

**7. 最初の貢献までの時間を測る。** 新しいメンバーが本番で実際の仕事を完了するまでにかかる時間と、何がそれを遅くするかを追跡します。アクセス、文書、環境のセットアップ、不明確なオーナーシップ。原因を直し、最近加わった人々に見方を尋ねます。速く支えのある出だしは、調子を決め、リスクを減らします（トピック 6.4「ユーザー体験と従業員体験」を参照）。

**8. 新しい人に、早くから支援付きの実際の仕事を与える。** 小さな実際のタスクと名前付きのバディから始めます。進捗を定期的にレビューし、調整します。安全網を伴う実践による学びは、長い読書の期間より速い。

### 学習を誠実に評価する

**9. 研修が適用されたかを尋ねる。** コースやイベントの後、数週間後に、学習者とそのチームに、それを使ったか、どう使ったかを尋ねます。答えを集約します。誰も適用しないコースは変更するか、やめるべきです。反応から学習、行動、結果へと進む、研修評価の四つの水準のカークパトリックモデルは、これのための語彙を提供しますが、単純なフォローアップの質問が良い出発点です。

**10. 認証を、得意なことに使う。** 法律、契約、役割の入口の基準が認証を要求するところでは、網羅率を追跡します。それ以外では、認証を労力と知識の一つのシグナルとして扱います。証明書の数を目標に設定してはならず、それだけで給与や昇進を決めてはいけません。

**11. 教訓をチーム間で共有する。** インシデント、レビュー、改善からの教訓の軽量な台帳を保ち、元のチーム以外のチームによって使われたものを追跡します。学んだチームにとどまる教訓は、組織にとって半分しか学ばれていません。実践コミュニティで台帳をレビューします。

**12. 個人のデータをランキングの外に置く。** スキルの棚卸しを人別に公表してはならず、研修時間、証明書、自己評価のスキルで人に順位を付けてはいけません。チームのレベルに集約し、人々が自分自身のデータを見られるようにします。ギャップが不利に数えられるなら、個人はそれを隠します。

## 悪用の手口と防護柵

| メトリクス | 悪用のされ方 | 組になる防護柵のメトリクスまたはプラクティス |
| --- | --- | --- |
| 守られた学習時間の割合 | 通常の仕事を学習として記録する、のちにキャンセルされる時間を予定する | 使われた時間のみを数える。作業の種類の記録とチームのコメントと比較する |
| クロストレーニングの深さ | 一度もそのタスクをしたことのない人を列挙する、単一の観察を数える | 最近の仕事の証拠。訓練の結果 |
| 最初の貢献までの時間 | 些細な変更を数える、時計を遅く始める | 台帳に「実際の」仕事を定義する。新しいメンバーとそのバディに尋ねる |
| コミュニティへの参加 | 出席を義務化する、登録を数える | 任意のみ。コミュニティが何を生んだかを尋ねる |
| 研修の適用率 | 適用したと言うよう学習者に圧力をかける、熱心な人にだけ尋ねる | 匿名の集約。チームのレベルでのフォローアップ。観察できる変化を見る |
| 関連する認証の網羅 | 必要のない役割のために証明書を集める、認証を能力として扱う | 真の要件に絞る。他の証拠で実際の能力を確認する |
| チーム間で共有された教訓 | 些細な教訓を共有する、投稿を数える | 別のチームによる記録された利用を要求する。質をレビューする |

健全な読みは、守られ使われている学習時間、複数の人に知られている重要なタスク、実際の貢献を素早く行う新しいメンバー、共有された実践を生むコミュニティ、人々が適用する研修、そしてチーム間を移動する教訓です。

## トレードオフ：長所と短所

| 手法 | 強み | 弱み |
| --- | --- | --- |
| 正式なコースと認証 | 構造化され、認められ、入口や規制対象の役割に有用 | コスト。仕事に移らないかもしれない |
| 仕事の中での学び | 関連性があり、直接的 | ばらつきがある。メンターと時間に依存する |
| 守られた時間 | 学習を現実のものにする | 緊急の仕事と競合する。規律が要る |
| 自分の時間での学習 | デリバリーにコストがかからない | 持続不可能。不公平。隠れた残業 |
| スキルの棚卸し | ギャップとリスクを示す | 主観的。ランキングになりうる |
| 最近の仕事の証拠 | 信頼できる | 維持により労力がかかる |
| 集中型の研修プログラム | 一貫性 | 遅い。チームに合わないかもしれない |
| チームが選ぶ学習 | 関連性があり、意欲的 | 質にばらつき。指針が要る |

散文での答えは、勤務週内に学習時間を守り、主に仕事を通じて、役立つところでは一部の正式なコースで学び、最近の証拠に基づいてスキルの地図を保ち、データを人の順位付けに使うのをすべて避けることです。

## チームで話し合う問い

**1. 先四半期に私たち各自が仕事で何を学び、どう学んだか？**
簡潔に共有します。学びの大半が、コース、仕事、同僚のどこから来たかに注意します。ファシリテーターは、何がそれを可能にし、何が妨げたかを尋ねてください。有用な学びを増やす変更を一つ合意します。

**2. 私たちのうち一人か二人しかできない重要なタスクはどれで、その人が不在のとき何が起きるか？**
それらを列挙します。最もリスクのあるものを選び、知識を広げる方法を計画します。ペアリング、訓練、手順書、ローテーション。計画が専門家に隠れた残業を加えないことを確認します。

**3. 最後の新しい同僚が何か実際のことをするのにどのくらいかかり、何がそれを遅くしたか？**
本人に尋ねます。最初の日からのステップをたどります。アクセス、環境、文書、支援を話し合います。次の人を助ける修正を二つ合意します。

**4. コースや証明書が私たちの働き方を変えたのはいつか？**
例を思い出します。何が違いを生んだかを尋ねます。ほとんど思い浮かばなければ、その理由を話し合います。どの学習を続ける価値があり、どれをやめるかを決めます。

**5. 最近のインシデントからの教訓で、別のチームが実際に使ったものは何か？**
教訓の台帳を見ます。何も移動していなければ、より効果的に共有する方法を尋ねます。コミュニティ、短い発表、標準の変更。今月共有する教訓を一つ選びます。

**6. 私たちの学習時間は現実のものか、何がそれを守っているか？**
計画を実際に起きたことと比較します。何がそれを奪うかを話し合います。インシデント、締め切り、期待。緊急の依頼を判断者へのエスカレーションとして扱うなど、守るための規則に合意します。

## 四つの視点

### プロダクトとデリバリーのチーム

デリバリーのチームは、主に作ることで学びます。学習時間を計画し、重要な仕事でペアリングとローテーションを行い、学んだことを共有し、実践コミュニティに参加するべきです。必要な時間とツールを求め、学習を、うまく届けることの一部として扱うべきです。

### サービスと運用のチーム

運用チームは、あらゆる時間の不在とインシデントをカバーするため、幅が必要です。重要なタスクをクロストレーニングし、訓練とゲームデーを使い、学んだことを手順書とレビューに取り込むべきです。オンコールのリズムは、休息と学びの余地を残さなければなりません。

### リーダーシップとガバナンス

リーダーは、学習が優先事項か後回しかを決めます。計画に学習時間を守り、オンボーディングが明らかにする修正に資金を付け、研修時間や証明書の目標を避け、コミュニティを支えるべきです。ガバナンスは、認証を必要なところでのみ追跡し、使われている能力の証拠を見るべきです。

### 顧客とユーザー

ユーザーは、サービスを深く知り、変化についていくチームから恩恵を受けます。より速い修正、繰り返される間違いの減少、より良い助言。助けてくれる人々がシステムに不慣れに見える、あるいは同じ問題が再発するときに気づきます。彼らはまた、自分の仕事についてチームに教えられ、彼らの関与は学びの一形態です。

## 実践：サービスマネジメントの例

地域銀行の技術運用グループには、勘定系、決済、デジタルチャネルを運営する六つのチームがあります。以下の数字は例示です。

グループの研修のダッシュボードは、昨年、一人あたり平均24時間の研修と70の取得された証明書を示し、研修の責任者は満足しています。運用の責任者は別の問いを投げかけます。主要な人々が不在のとき、チームは対処できるか。彼女は各チームに、重要なタスクと、直近6か月にそれぞれを実行した人をマップするよう頼みます。46の重要なタスクのうち、二人以上が実行したのは19件だけで、クロストレーニングの深さは41パーセントでした。14件のタスクは一人が行っていました。直近の8人の採用の最初の貢献までの時間は中央値41日、85パーセンタイルは67日で、ほとんどはアクセスの待ちと文書探しに費やされています。コースを修了した38人へのフォローアップでは、31パーセントが90日以内に学びを適用したと述べました。チームは、学習時間が忙しい週に真っ先にキャンセルされるものだと報告し、実際に使われた守られた時間はキャパシティの約3パーセントです。

グループは、チームとともに四つの変更を行います。各チームが、キャパシティの約8パーセントの常設の学習ブロックと、キャンセルはチームのリードとの合意と記録が必要という規則を計画します。ペアリングとローテーションの計画が、14件の一人のタスクを対象とし、最も重要な五件から始め、四半期ごとの訓練を伴います。オンボーディングのチェックリストと名前付きのバディがアクセスの遅れを削減し、最初の週の計画に小さな実際の変更が含まれます。コースは短いリストからチームが選び、60日後にフォローアップの質問が送られます。信頼性についてのチーム横断のコミュニティが毎月集まり、インシデントのレビューからの教訓が、誰が使ったかのメモとともにそこで共有されます。

1年後、クロストレーニングの深さは78パーセント、最初の貢献までの時間の中央値は19日、研修の適用率は64パーセント、使われた守られた学習時間はキャパシティの約7パーセントです。レビューからの六つの教訓が、他のチームに採用されました。研修の責任者は、一人あたり40時間の研修の目標を求めます。運用の責任者は、代わりにクロストレーニングの深さ、適用、最初の貢献までの時間の測定値を提案し、時間は誰も使わないセッションで満たせると説明します。判断は記録され、ダッシュボードは平均の研修時間を落とします。認証の網羅は、規制当局が求める役割についてのみ追跡されます。

## アジャイル、AI、自動化、アナリティクス

### アジャイル

持続可能なペースの中で学習時間を守り、定期的なレビューを通じて教訓を共有します。注意点は、研修時間の目標は、学びではなく出席を生むことです。

### AI

AIは、AIの出力を確認すること、良いプロンプトを書くこと、限界を理解することなど、チームが必要とするスキルを変えます。コースの修了ではなく、仕事への学びの適用とAI支援の仕事の質を測ります。注意点は、AIツールの証明書は実践より遅れうるもので、能力を証明しないことです。

### 自動化

学習のリマインダーとスキルのマッピングへの入力を自動化し、学習コンテンツの利用を測ります。注意点は、活動データからの自動のスキルの推論は不正確で侵襲的でありうることです。

### アナリティクス

クロストレーニングの深さを、チーム別に件数とともに示します。これが情報を与える判断は、知識がどこで危険にさらされているかです。注意点は、スキルのマトリクスは古くなるので、レビューすることです。

## 業種別の視点

**スタートアップ。** 人々は多くの役割を担い、圧力のもとで速く学びます。学習のためにいくらかの時間を守り、ペアリングを既定とし、知識の単一の点に注意します。ジェネラリストの採用が助けになります。研修の部門を早すぎる時期に築かないでください。

**中小企業。** 予算は厳しく、一人が多くをカバーするかもしれません。低コストの学習を使います。ベンダーの文書、コミュニティのイベント、信頼できる外部の助言者によるメンタリング、可能ならクロストレーニング。たとえ大まかにでも、少なくとももう一人が重要なタスクを扱えることを確認します。

**大企業。** 規模は、正式なプログラム、コミュニティ、キャリアパスを可能にします。誰にも合わない一律の要件も招きます。共通の学習予算とプラットフォームを提供し、チームに選ばせ、社内のコミュニティを支え、能力をチーム別に測ります。認証を本当の必要に整合させます。

**政府・公共部門。** スキル不足、調達規則、公務員の枠組みが、能力開発を形作ります。認証は一部の役割の正式な要件かもしれません。見習いと内部の異動に投資し、契約が終わるときに知識を保持し、機関間のコミュニティを使って実践を共有します（トピック 8.5「規制対応・行政向け報告」を参照）。

## ビジネスケース：動機、ROI、TCO

コストは、主なコストである時間そのものに加えて、コースとイベントの予算、スキルの地図を維持する労力、メンタリングの時間、コミュニティのための一定のツールです。ペアリングとローテーションは、短期的にはスループットを犠牲にします。

見返りは、不在と離職への耐性、より速いオンボーディング、繰り返される間違いの減少、より速い問題解決、成長している人々のより良い定着です。自分たち自身のデータからケースを築きます。一人に知られている重要なタスクの数、新入社員が生産的になるまでにかかる日数とその時間のコスト、不在の専門家によって長引いたインシデント、成長の余地がないと言うスタッフの離職。方法と適合をたどれない限り、研修の見返りについての公表された見積もりの引用は避けます。学ばないことのコストは、時代遅れのスキルと壊れやすいサービスとして、遅れて現れます（トピック 7.7「投資対効果とビジネスケース」を参照）。

## アンチパターンと落とし穴

- **目標としての研修時間。** 出席を買う。適用と能力を測る。
- **スキルの証明としての証明書。** ある時点の評価を示す。他の証拠を使う。
- **自分の時間での学習。** 残業を隠し、不公平である。勤務週内に時間を守る。
- **ランキングに使われる自己評価のスキルの棚卸し。** 人々は水増しまたは隠す。地図を最近の仕事に基づかせ、チームのレベルに保つ。
- **英雄的な専門家。** すべてを知る一人はリスクであり負担である。知識を広げる。
- **全員に中央で選ばれたコース。** ほとんど合わない。指針とともにチームに選ばせる。
- **学習を真っ先にキャンセルする。** 学習が任意だと教える。守り、例外を判断として扱う。
- **ローカルにとどまる教訓。** 組織が間違いを繰り返す。共有し、利用を追跡する。

## チェックリスト

- [ ] 学習時間がチームのキャパシティに計画され、使われたものとして追跡されている。
- [ ] 重要なタスクが、それぞれを最近実行した人とともに列挙されている。
- [ ] すべての重要なタスクに、少なくとも二人の実践した人に達する計画がある。
- [ ] 新しいメンバーの最初の貢献までの時間が測定され、対処されている。
- [ ] 実践コミュニティとメンタリングが支えられ、任意である。
- [ ] 研修が、適用についての質問でフォローアップされている。
- [ ] 認証が、真の要件のある役割にのみ追跡されている。
- [ ] 教訓の台帳が、チーム間の共有と利用を記録している。
- [ ] スキルのデータがチームのレベルに保たれ、個人の順位付けに使われていない。
- [ ] 学習が無給の時間に依存していない。

## AIプロンプト

**重要なタスクの地図を築く。**

```text
私たちのチームは [サービス] を運営しています。確実に行われなければならない重要なタスク（たとえばバックアップからの復旧、認証情報のローテーション、重大インシデントの調整、リスクのあるデプロイ）を列挙し、直近6か月にそれぞれを誰が行ったかを記録するのに使える証拠を示唆してください。単純な表と、人々に順位を付けずにチームとレビューする方法を提案してください。私が述べたものを超えて、私たちのタスクを捏造しないでください。前提を列挙してください。
```

**オンボーディング計画を設計する。**

```text
[サービス] を運営するチームに加わる新しい [役割] のための、最初の30日のオンボーディング計画を設計してください。アクセスの設定、名前付きのバディ、最初の週の終わりまでの小さな実際の変更、定期的なチェックイン、測るもの（最初の貢献までの時間と何がそれを遅くしたか）を含めてください。支えがあり、現実的にしてください。前提と、私たちの文脈に合わせるべき項目を列挙してください。
```

**研修をフォローアップする。**

```text
[コースまたはイベント] を修了した人々に60日後に送る、短いフォローアップの質問の集合を起案してください。個人を特定せずにチームのレベルに集約できる形で、それを適用したか、どう適用したか、何が妨げたか、何が助けになるかを尋ねてください。答えをどう読み、何を変えるかを示唆してください。前提を列挙してください。
```

**知識を広げる取り組みを計画する。**

```text
タスク [説明] は、私たちのチームで [一人か二人] しか行っていません。ペアリング、訓練、文書を使ってそれを広げる計画を、その人々の作業負荷を守る現実的なタイミングで提案してください。最近の仕事の証拠を使って、計画が機能したかをどう知るかを示唆してください。前提とリスクを列挙してください。
```

## AIスキル

- [サービスマネジメントメトリクスのスキル](../../../../skills/service-management-metrics-skill/SKILL.md)：スキルまたは学習のメトリクスの、組になる防護柵を探すときに使います。
- [サービスマネジメントメトリクスのメンテナースキル](../../../../skills/service-management-metrics-maintainer-skill/SKILL.md)：学習のメトリクスの項目が、使われている能力を測り、悪用の手口と防護柵を備えているかを確認するときに使います。

## 要点

- 使われている能力を測る。誰が最近重要なタスクを行ったか、新しい人がどれだけ速く貢献するか。
- 持続できるペースの中で、勤務週内に学習時間を守る。
- ペアリング、ローテーション、訓練、コミュニティを通じて、意図して知識を広げる。
- 研修が適用されたかをフォローアップし、証明書を証明ではなく証拠として扱う。
- 教訓をチーム間で共有し、その利用を追跡する。
- スキルのデータをチームのレベルに保ち、個人に順位を付けない。
