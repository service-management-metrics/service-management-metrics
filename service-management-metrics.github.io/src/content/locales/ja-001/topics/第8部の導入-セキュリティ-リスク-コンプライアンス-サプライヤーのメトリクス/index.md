# 第8部の導入：セキュリティ、リスク、コンプライアンス、サプライヤーのメトリクス

**サービスへの信頼は、それが脅威、リスク、義務、その背後の第三者をどう扱うかにかかっている。その信頼の最良の証拠は、仕事そのものが生み出し、公然と共有される。**

サービスは、速く、安く、好まれていても、パッチ未適用の弱点、検討されていないリスク、誰も追跡しなかった義務、あるいは提供をやめた供給者のために、それに依存する人々を失望させうるものです。この部の測定値は、それらの失敗に対して守る条件を記述します。弱点がどれだけ長く開いたままか、統制が機能しているか、誰かが求めたときに証拠が存在するか、そして何に依存しているかを知っていて、そこから離れられるか。

アジャイルの実践もITILも、これらの関心を、異なる角度から真剣に扱います。ITILは、情報セキュリティ管理、リスク管理、サプライヤー管理、ガバナンスを、ポリシー、オーナーシップ、記録への重点とともにもたらします。アジャイルとDevOpsは、セキュリティと統制が継続的デリバリーの内側に属するという考えをもたらします。小さな変更、速いフィードバック、自動化された確認、開発、セキュリティ、運用、保証の間の共有された責任。最も効果的な組織は二つを組み合わせ、統制がパイプラインに組み込まれ、証拠がデリバリーの副産物となり、監査人、規制当局、供給者が、時折の敵対者ではなく、継続する対話のパートナーになります。

これらの測定値はまた、歪みの最も高い危険性を伴います。所見、赤いリスク、侵害の目標は、人々に目をそらす、再評価する、隠すことを教えます。不審な活動の報告のような、人間の行動に触れる測定値は、監視や非難に滑り込みうるものです。したがって、この部のすべてのメトリクスには、悪用される方法と防護柵が付いており、この部は安全な報告と非難なき学びを、それ自体が統制として扱います。どの測定値も、個人に順位を付けません。システム、サービス、関係を記述します（トピック 1.2「グッドハートの法則とメトリクスの心理学」を参照）。

AIシステムが新しいリスクと新しい義務を加えるため、四つのレンズはここで重要です。セキュリティとコンプライアンスの証拠は、パイプラインによってますます生み出されるので、自動化は信頼ではなく、テストされなければなりません。供給者はAIを組み込んでいるかもしれないので、何がオンになっているかを尋ねます。アナリティクスは、露出と統制の有効性を標本サイズとともに報告します。この本は法的助言を与えないので、義務は自分の法律顧問と確認してください。

## この部のトピック

- **8.1 セキュリティインシデントと脆弱性のメトリクス**：露出の窓、パッチの順守、スキャンの網羅率、封じ込めまでの時間、例外、シグナルを流れ続けさせる報告の文化。
- **8.2 リスクと統制のメトリクス**：短くオーナーのいるリスク台帳、統制のテスト、主要リスク指標、リスクに基づく変更の承認。
- **8.3 コンプライアンスと監査のメトリクス**：義務の網羅率、証拠の自動化、所見のクローズと繰り返し、監査人との協働。
- **8.4 サプライヤーと契約のメトリクス**：体験に照らした供給者のパフォーマンス、集中、デューデリジェンス、共同のレビュー、テストされた撤退計画。
- **8.5 規制対応・行政向け報告**：設計への入力としての報告義務、たどれるレポート、突合された定義、使える公的情報。

## これらのトピックの相互関係

セキュリティの測定値（トピック 8.1「セキュリティインシデントと脆弱性のメトリクス」を参照）は、脅威と弱点を具体的な言葉で記述し、リスク台帳のための最も強い主要リスク指標のいくつかを供給します。リスクと統制の測定値（トピック 8.2「リスクと統制のメトリクス」を参照）は、それらの指標を文脈の中に置き、どの統制が重要かを決め、それらが機能することをテストします。コンプライアンスと監査の測定値（トピック 8.3「コンプライアンスと監査のメトリクス」を参照）は、同じ統制とテストを部外者のための証拠に変え、その証拠のどれだけを仕事自体が生み出すかを示します。

供給者の測定値（トピック 8.4「サプライヤーと契約のメトリクス」を参照）は、これらそれぞれを組織の境界を越えて拡張します。供給者の脆弱性、リスク、コンプライアンスの姿勢は自分たちのものになり、契約は統制の一つです。報告のトピック（トピック 8.5「規制対応・行政向け報告」を参照）は、誰に何を言わなければならないか、報告の見方がそれが記述する仕事を歪めることなく、それをどう正確に言うかを問うことで、この部を閉じます。

いくつかの防護柵の組が導かれます。露出の窓は、きれいな数字が単に狭いスキャンではないよう、スキャンの網羅率とともに読まれるべきです。統制の有効性の率は、完璧な率が弱いテストから来うるため、失敗のフォローアップとともに読まれるべきです。監査の所見の件数は、繰り返しの率とクローズの検証とともに読まれるべきです。供給者のサービスレベルは、ユーザー体験とともに読まれるべきです（トピック 6.2「体験レベル合意」を参照）。法定の数字は、その相棒の測定値と、社内の定義との突合とともに読まれるべきです。

この部は前の部に頼っています。資産、構成、コストの記録（トピック 7.1「IT資産管理のメトリクス」とトピック 7.4「構成とCMDB品質のメトリクス」を参照）は、スキャン、依存関係のマッピング、供給者の分析を可能にするものです。第4部のポストモーテムと変更の測定値は、この仕事を誠実に保つ学びのループを供給します。第9部は、そのすべての背後にいる人々に目を向けます。彼らの健全性、協働、そしてシステム全体を時間とともにより良くする改善の習慣。
