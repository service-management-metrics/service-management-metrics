# 第11部の導入：メトリクスプログラムを築く

**メトリクスプログラムは、それ自体が長寿命のサービスである。聞き手、少数の測定値、誠実なツール、測られる人々の信頼、そして一歩ずつ育つ道筋が要る。**

第2部から第10部は、何を測るかを述べています。この部は、それらの測定値を、続く習慣に変える方法を述べます。多くの組織は、測定をプロジェクトとして扱います。ツールを選び、ダッシュボードを築き、一連の目標を告知し、先へ進む。1年後、ダッシュボードは古くなり、目標は誰も意図しなかった形で行動を曲げ、測られた人々は、この取り組み全体を信用しないことを学んでいます。プログラムは違います。オーナー、目的、レビューの頻度、役立たなくなった測定値を廃止する方法があります。それ自体がサービスであり、他のサービスと同様に測定し改善できます。

アジャイルの狙いは、他のあらゆる仕事に当てはまるのと同じようにプログラムにも当てはまります。ステークホルダーの継続的な関与は、測られる人々と、結果を使う人々が、最初から測定値の選択を手伝うことを意味します。継続的改善は、プログラムが自らをレビューし、コストに値しないものを落とすことを意味します。継続的な進化は、サービスが変わるにつれて測定値の集合が変わることを意味します。持続可能なペースは、プログラムが、照らし出すはずの仕事を押しのける報告の負担を加えないことを意味します。そして意欲のある個人を中心に築くことは、測定値が監視として押し付けられるのではなく、自分たちの仕事を所有するチームへの助けとして提供されることを意味します（トピック 1.2「グッドハートの法則とメトリクスの心理学」を参照）。

あらゆるプログラムには、二つの静かな失敗が付きまといます。一つ目は恐れです。数字がランク付け、非難、削減に使われると人々が信じれば、仕事ではなく数字を管理するようになり、データは真実でなくなります。二つ目は無秩序な拡大です。すべてのステークホルダーがもう一つの測定値を求め、すべてのツールがさらに50のチャートを提供し、やがて誰も、どの数字が重要かを言えなくなります。この部のトピックは、主にこれら二つの失敗を避けることについてです。集合を小さく保ち、チームが所有し、その使われ方を目に見えて穏やかなものに保つ。

四つのレンズが、メトリクスプログラムを形作ります。それは、測るサービスと同じ継続的デリバリーの精神で築かれるべきです。ツールのAI機能と、人についてのAI由来のデータには、明示的な規則が要ります。自動化は収集の労力を減らし、他の自動化と同じオーナーシップと確認が要ります。データ品質と不確実性を伴うアナリティクスの実践が、プログラムの出力を読む価値のあるものにします。

## この部のトピック

- **11.1 サービスメトリクスのダッシュボード設計**：聞き手、小さくバランスの取れた集合、文脈と傾向、チーム、サービス、リーダーシップのための見方。
- **11.2 ツールの全体像**：自作か購入か、プラットフォームの種類、データパイプライン、ベンダー中立の選定基準。
- **11.3 恐れを生まずにメトリクスを展開する**：透明性、チームのオーナーシップ、個人のランキング表なし、信頼を得る展開。
- **11.4 メトリクスプログラムの成熟度モデル**：プログラム自体に適用される、共有の5段階の尺度。
- **11.5 段階的な導入ロードマップ**：今いる場所から始まる、最初の30日、90日、180日の計画。

## これらのトピックの相互関係

恐れのない展開（トピック 11.3「恐れを生まずにメトリクスを展開する」を参照）は、人々が目にするのがダッシュボードであっても、重要性で最初に来ます。誰がデータを所有し、誰が見て、何には決して使われないかについての合意が、どのダッシュボードも真実の数字を運ぶかを決めます。ダッシュボードのトピック（トピック 11.1「サービスメトリクスのダッシュボード設計」を参照）は、それらの合意を設計に変えます。小さな集合、文脈、傾向、各聞き手に合った見方。ツールのトピック（トピック 11.2「ツールの全体像」を参照）は、そのうえで、便益より大きなプロジェクトにならずにデータを供給できるプラットフォームとパイプラインはどれかを問います。

成熟度モデル（トピック 11.4「メトリクスプログラムの成熟度モデル」を参照）は、他のあらゆるトピックと同じ尺度を使って、プログラムが今どこにいて、次のステップが何でありうるかを記述する方法を与えます。ロードマップ（トピック 11.5「段階的な導入ロードマップ」を参照）はそれを、小さなステップの計画に変え、各ステップが、次が始まる前に、測られる人々にいくらかの価値を届けます。これは、この本の残りがサービスに推奨するのと同じ継続的デリバリーの論理です。役立つものを早く出荷し、その利用から学び、改善する。

いくつかの組み合わせが、プログラムを誠実に保ちます。結果のダッシュボードは、データがどう収集されたかの記録と、既知のギャップとともに読まれるべきです。展開の計画は、データが何に使われないかの約束とともに読まれるべきです。ツールの選択は、それを離れるコストとともに読まれるべきです。成熟度のスコアは、対話の契機として扱い、目標としては決して扱いません。

この部は、第1部の基礎、特にメトリクスのガバナンス（トピック 1.4「メトリクスのガバナンスとオーナーシップ」を参照）とデータソース（トピック 1.5「データソースと計装」を参照）、そして第9部の改善と変更の測定値（トピック 9.5「継続的改善のメトリクス」とトピック 9.6「組織変革と定着のメトリクス」を参照）に依拠しています。第12部の付録は、プログラムのチームが日々使うチェックリスト、テンプレート、統合された参考文献を提供します。
