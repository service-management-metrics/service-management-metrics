# コンプライアンスと監査のメトリクス

**コンプライアンスは、証拠が仕事そのものによって生み出されるときに、最も容易で誠実になる。したがって、どれだけの証拠が自動で来るか、所見がどれだけ速く直されるか、同じ所見がどのくらいの頻度で戻るかを測り、監査人を、早期に対話に加わるステークホルダーとして扱う。**

## 概要と動機

ITサービスを構築し運営するほとんどの組織は、誰かに対して責任を負っています。規制当局、顧客、認証機関、保険会社、取締役会。[規制の遵守（regulatory compliance）](https://en.wikipedia.org/wiki/Regulatory_compliance)は、法律、規則、規格に従い、そうしていることを示す行為です。監査は、それが真かを判断するための、証拠の体系的な検査です。ITでは、財務報告の統制、データ保護の義務、セキュリティの認証、契約上のコミットメントの監査が含まれます。[IT監査（information technology audit）](https://en.wikipedia.org/wiki/Information_technology_audit)は、システムとそれが保持するデータをめぐる統制を検査します。

コンプライアンスと継続的デリバリーには、摩擦があるという評判があります。コンプライアンスは変更の前に文書、署名、承認を求め、継続的デリバリーは継続的にリリースされる小さな変更を好みます。コンプライアンスが終わりの段階として扱われるとき、摩擦は現実のものです。コンプライアンスが仕事の流れに組み込まれると、和らぎます。変更の記録、コードレビュー、自動テスト、アクセスのログは証拠であり、デリバリーのパイプラインは毎日それらを生み出します。[継続的監査（continuous auditing）](https://en.wikipedia.org/wiki/Continuous_auditing)は、定期的な抽出の代わりに、統制の自動化されたほぼリアルタイムの確認を使い、継続的デリバリーの周期に合います。[監査証跡（audit trail）](https://en.wikipedia.org/wiki/Audit_trail)は、誰が、いつ、どのシステムに何をしたかを示す記録で、持っている最も強い証拠であることが多くあります。

ITILは関連するプラクティスを記述しています。情報セキュリティ管理、リスク管理、サービス価値システムのガバナンスで、情報セキュリティ管理システムのための[ISO/IEC 27001](https://en.wikipedia.org/wiki/ISO/IEC_27001)などの規格を指します。組織が一般的に直面する枠組みには、米国の[サーベンス・オクスリー法（Sarbanes–Oxley Act）](https://en.wikipedia.org/wiki/Sarbanes%E2%80%93Oxley_Act)のような財務統制の報告制度、欧州連合の[一般データ保護規則（General Data Protection Regulation）](https://en.wikipedia.org/wiki/General_Data_Protection_Regulation)のようなデータ保護法、セキュリティと関連する基準に関連する統制を検査する[SOC 2](https://en.wikipedia.org/wiki/SOC_2)のような保証レポートがあります。詳細は法域、業種、日付によって異なり、このトピックは法的要件ではなく、測定の実践を記述します。自分に何が適用されるかは、コンプライアンス、法務、監査の同僚と確認してください。

コンプライアンスのメトリクスの狙いは、組織が義務をどれだけうまく満たし、そのためにどれだけの労力がかかるかを学び、両方を改善できるようにすることです。リスクは、コンプライアンスが監査人のための演技になることです。チームは、直前に文書を作成して監査に合格しながら、危うい実践を運用し続けられます。[グッドハートの法則（Goodhart's law）](https://en.wikipedia.org/wiki/Goodhart%27s_law)からの防護柵が当てはまります。「監査の所見」が目標になると、人々は精査を避け、範囲を狭め、文言を交渉します（トピック 1.2「グッドハートの法則とメトリクスの心理学」を参照）。

二つの考え方が役立ちます。

- **副産物としてのコンプライアンス。** パイプラインがレビュー、テスト、承認、デプロイを自動で記録するなら、監査が近いかどうかにかかわらず、証拠が存在する。これは、事後に証拠を再構成する誘惑も取り除く。
- **ステークホルダーとしての監査人。** アジャイルの実践は、ステークホルダーとの継続的な協働を重んじる。監査人と評価者は、正当な問いを持つステークホルダーである。統制と証拠の設計に彼らを巻き込むことは、独立性を保ちながら、驚きと手戻りを減らす。

## 主要な原則

- **仕事の副産物として証拠を生み出す。** パイプライン、チケット、ログが、ほとんどの監査の問いに答えるべきである。
- **義務を統制とオーナーに対応づける。** すべての義務に統制があり、すべての統制にオーナーがいる。
- **監査人と早期に協働する。** 監査の前に、設計と証拠のアプローチを共有し、彼らの独立性を保つ。
- **所見ではなく、原因を直す。** 原因を取り除かずにクローズされた所見は、戻ってくる。
- **成果に加えて、労力を測る。** コンプライアンスのコストは、絵の一部である。
- **重要なところで職務分掌を保つ。** レビューの独立性は、自動化が支えられるが、置き換えられない統制である。
- **ギャップについて誠実である。** 自己申告された弱点は、他人に見つけられるより、自分で見つけるほうがよい。

## 推奨事項

### 義務と統制を知る

**1. 適用される義務を平易な言葉で列挙する。** 法務とコンプライアンスの同僚とともに、サービスを拘束する法律、規格、契約、ポリシーと、それぞれが成果の観点で何を求めるかを列挙します。一覧を短く読みやすく保ちます。誰も平易に述べられない義務が、監査の驚きを引き起こすものです。

**2. 各義務を統制、オーナー、証拠に対応づける。** 各義務について、それを満たす統制、責任を負う人、統制が運用されていることを示す証拠に名前を付けます。一つの統制が複数の義務を満たすところでは、そう述べます。それが重複した労力を減らすからです。義務の網羅率が、この地図の完全性を測ります。対応づけられていない義務は、閉じるか、承知の上で受容するギャップです。

**3. より少なく、より強い統制を好む。** 自動化されテストされた統制は、いくつもの手作業のものに匹敵します。重複する統制を探し、どの義務にも役立たないものを廃止します。各統制は、運用し、証拠を示す労力がかかります（トピック 8.2「リスクと統制のメトリクス」を参照）。

### 証拠を副産物にする

**4. パイプラインに証拠を生み出させる。** すべての本番の変更を、依頼、コードレビュー、テスト結果、必要な場合は承認に結び付け、すべて自動で記録します。これらを示すデプロイの記録は、文書が書かれることなく、何が起きたかを監査人に伝えます。これは、アジャイルのチームがすでに使っている継続的デリバリーの実践に依拠します（トピック 4.5「リリースとデプロイのメトリクス」を参照）。

**5. パイプラインでポリシーの確認を使う。** 「作者以外によるレビューのないデプロイはしない」「チケットなしの本番アクセスはしない」などの規則を、自動化された確認として符号化します。確認は統制であり、その証拠でもあります。規則を見えるようにバージョン管理し、規則の変更も記録されるようにします。これは、機微なプロセスのすべての段階を一人が統制すべきではないという原則である[職務分掌（segregation of duties）](https://en.wikipedia.org/wiki/Segregation_of_duties)を支えます。

**6. 監査証跡を適切に保存する。** アクセスと変更のログを、それが記述する人々によって変更できない形で保ち、必要な期間保持し、検索可能にします。記録される人が編集できる証跡は、弱い証拠です。保持の規則を法務の同僚と確認します。

**7. どれだけの証拠が自動かを測る。** 証拠の自動化率は、手作業の収集がどこに残っているかを示します。手作業のアイテムを労力とリスクで順位付け、最悪のものを先に自動化します。率が上がるにつれて、監査の労力と対応時間が下がります。

### 監査人と協働する

**8. 監査人を設計に招く。** 統制と証拠への計画された変更を、内部監査と外部の評価者に早く共有し、何が彼らを満足させるかを尋ねます。独立性とは、彼らがあなたの統制を設計しないことを意味し、必要になる証拠を彼らがあなたに伝えられないことを意味しません。早期の対話は手戻りを減らします。内部監査人協会は、[内部監査（internal audit）](https://en.wikipedia.org/wiki/Internal_audit)の役割を説明する、専門職のための規格を公表しています。

**9. 証拠の索引を用意する。** 各種類の証拠がどこにあり、どう取り出すかの生きた索引を保ちます。証拠の依頼の対応時間を追跡し、遅れを使って欠けている自動化を見つけます。短く安定したプロセスは、各監査の前の慌てに勝ります。

**10. 重要性と範囲の意味に合意する。** 監査人に、何が重要で何が範囲内かをどう判断するかを尋ね、答えを記録します。共有された理解が、後の争いを防ぎます。精査を避けるために範囲を狭めたり、理由なく広げたりしないでください。

### 原因を直して学ぶ

**11. 各所見を問題レコードとして扱う。** 原因を見つけ、直し、独立した誰かにクローズを検証してもらいます。繰り返される所見を以前のものにリンクし、最初の修正がなぜ保たれなかったかを調べます。高い繰り返される所見の率は、症状を扱った修正を指し、問題管理に結び付きます（トピック 4.1「問題管理のメトリクス」を参照）。

**12. コストを追跡して下げる。** 周期にわたって監査の労力を記録します。労力が高く横ばいなら、監査間の重複、手作業の証拠の収集、誰にも役立たない統制を探します。労力の傾向を成果とともに報告します。コンプライアンスは、本当のリスクを減らすときにコストに見合い、メトリクスはそれを見分ける助けになります。

## 悪用の手口と防護柵

| メトリクス | 悪用のされ方 | 組になる防護柵のメトリクスまたはプラクティス |
| --- | --- | --- |
| 義務の網羅率 | 義務を弱い、あるいは無関係な統制に対応づける、義務を狭く定義する | 第二者による統制の関連性のレビュー。統制をテストする（トピック 8.2「リスクと統制のメトリクス」を参照） |
| 証拠の自動化率 | スクリーンショットやエクスポートを自動として数える、価値の低い証拠を先に自動化する | 自動をシステムが生成し、改ざんに強いものと定義する。リスクで順位付ける |
| 証拠の対応時間 | 部分的な証拠を素早く提供する、依頼の文言を交渉する | 受理された証拠のみを数える。フォローアップの依頼を追跡する |
| 所見のクローズ時間 | 検証なしに所見をクローズする、深刻度を再分類する | 独立した検証。深刻度の変更ログ |
| 繰り返される所見の率 | 一致しないよう所見を言い換える、以前の所見を別の種類としてクローズする | 記録された規則で原因により照合する。内部監査によるレビュー |
| 職務分掌の衝突 | 衝突を範囲外のシステムに移す、決して記録されない一時的なアクセスを付与する | 機微なプロセスを持つすべてのシステムをカバーする。一時的なアクセスをレビューする |
| 監査の労力 | 時間を記録しない、労力を他の予算に移す | 時間の記録を抽出する。チームのアンケートと比較する |

健全な読みは、上がる証拠の自動化、より短く安定した対応時間、検証を伴ってクローズされる所見、低い繰り返しの率、そしてプロセスが成熟するにつれて下がる監査の労力です。

## トレードオフ：長所と短所

| 手法 | 強み | 弱み |
| --- | --- | --- |
| 定期的な手作業の証拠 | 監査人になじみがある | 高コスト。事後に再構成される |
| 自動化された継続的な証拠 | 維持が安く、適時 | エンジニアリングが要る。監査人が情報源を信頼する必要がある |
| 重い承認 | 見える統制 | 遅い。変更をまとめる |
| 自動化されたポリシーの確認 | 一貫して速い | 規則が正しく、見えている必要がある |
| 監査人の早期の関与 | 驚きが少ない | 独立性を保つ注意が要る |
| 終わりの監査 | 明確な分離 | 遅い所見。手戻り |
| 多くの義務に一つの統制 | 効率的 | 単一の失敗が複数の義務に影響する |
| 多くの特定の統制 | 明確な対応づけ | 重複した労力 |

散文での答えは、パイプラインと記録システムから証拠を自動化し、独立性を保ちながら設計の早い段階で監査人を関与させ、義務に対応づけられた強い統制の無駄のない集合を保つことです。

## チームで話し合う問い

**1. 私たちが答えるのに最も時間のかかる監査の質問はどれで、なぜか？**
直近の監査で最も遅かった証拠の依頼を選び、たどります。証拠は欠けているか、散らばっているか、誰かの頭の中にあるか。何がそれを自動にするかを話し合います。ファシリテーターは、コストを時間で記録してください。

**2. 先月の本番の変更について、誰がレビューし、どのテストが動いたか、示せるか？**
無作為に変更を一つ選んで試します。連鎖がどこで壊れるかに注意します。ギャップを閉じる、変更の記録またはパイプラインへの改善を一つ合意します。

**3. 前回の監査で何を約束し、それは保たれたか？**
所見と修正をレビューします。それぞれについて、原因が取り除かれたか、誰がクローズを検証したかを尋ねます。繰り返しを探します。より深く調べる所見を一つ合意します。

**4. 証拠を容易にする方法を尋ねたら、監査人は何と言うか？**
証拠の設計について、内部監査または評価者との対話を計画します。彼らが何を信頼し、何を信頼しないかを尋ねます。ファシリテーターは、彼らの答えを情報として扱い、独立性の規則を念頭に置いてください。

**5. どの義務も必要としない、私たちが運営している統制はどれか？**
統制と、それが役立つ義務を列挙します。明確な目的のないものを見つけます。それらを廃止することと、それが不要である証拠を話し合います。

**6. ここで、一人が機微なことをエンドツーエンドで行えるのはどこか？**
デプロイ、アクセスの付与、支払いを考えます。ツールが分掌を強制しているか、ポリシーだけかを確認します。スタッフの数が少ないところでの、自動化されたレビューのような補完統制を話し合います。

## 四つの視点

### プロダクトとデリバリーのチーム

デリバリーのチームは、仕事をうまく行うことで証拠の多くを生み出します。変更、レビュー、テストの記録をリンクさせ、パイプラインのポリシーの確認を使い、リスクを減らさずに仕事を遅くする統制についての懸念を挙げるべきです。どれだけの証拠で十分かについての、監査人との早期の対話から恩恵を受けます。

### サービスと運用のチーム

運用チームは、多くの監査の中心である、アクセス管理、ログ、バックアップ、インシデント対応を運営します。ログを改ざんに強く保持し、予定どおりにアクセスのレビューを管理し、証拠の索引を保つべきです。手作業の証拠の負担を負い、自動化がどこで最も役立つかを指摘できます。

### リーダーシップとガバナンス

リーダーは、コンプライアンスに責任を負い、しばしば監査の成果にも責任を負います。証拠の自動化に資金を付け、所見の件数だけでなく網羅率と繰り返される所見の率を求め、監査人の独立性を支えるべきです。ガバナンスは、ギャップの誠実な報告と、それぞれの計画を期待するべきです。

### 顧客とユーザー

顧客とユーザーは、自分たちのデータとサービスがどう扱われるかの保証として、コンプライアンスに頼ります。保証レポートが明確なとき、インシデントが必要に応じて報告されるとき、統制が正当な利用を必要以上に難しくしないときに、恩恵を受けます。コンプライアンスについての透明なコミュニケーションが、信頼を築きます。

## 実践：サービスマネジメントの例

中規模の決済会社が、カード処理の基盤を運営し、セキュリティ保証の枠組みとデータ保護の制度に対して毎年評価されています。以下の数字は例示です。

監査の準備に、エンジニアリングチームは毎年約6週間かかります。昨年の評価は14件の所見で終わり、そのうち5件は前年から繰り返されました。コンプライアンスの責任者は状況を整理します。義務の網羅率は83パーセントで、17パーセントの義務には名前付きの統制のオーナーがいません。証拠の自動化は22パーセントで、変更承認の証拠のほとんどは、手作業でまとめたチケットのスクリーンショットから来ています。証拠の対応時間の中央値は9日で、85パーセンタイルは21日です。所見のクローズ時間の中央値は74日で、クローズはしばしば検証なしに所有するチームによって印を付けられました。

コンプライアンスの責任者は、デリバリーと運用のチーム、内部監査人とともに働きます。彼らは四つのことを変えます。パイプライン内のすべての本番の変更は今、依頼、作者以外によるコードレビュー、テスト結果、デプロイに結び付けられ、変更の記録に自動で記録されます。ポリシーの確認が、独立したレビューのないデプロイをブロックし、緊急の経路の例外を記録します。アクセスのレビューは、アイデンティティシステムから四半期ごとに実行され、職務分掌の衝突を直接示します。各所見は問題レコードになり、内部監査からの独立した検証者が付き、繰り返される所見はその前身にリンクされます。

次の評価では、証拠の自動化率は71パーセント、証拠の対応時間の中央値は2日、85パーセンタイルは5日で、監査の準備には約2週間かかります。義務の網羅率は97パーセントで、残りの項目には文書化された受容があります。所見は6件に減り、繰り返しは1件で、クローズ時間の中央値は独立した検証を伴う31日です。最高経営責任者は、来年は所見ゼロを求めます。コンプライアンスの責任者は、繰り返される所見、クローズ時間、証拠の自動化を追跡することを提案し、所見ゼロの目標はチームに問題を隠す、あるいは範囲を狭めるよう促し、何も見つけない評価者は十分に見ていないのかもしれないと説明します。判断は記録され、取締役会は次の会議で測定値をレビューすることに合意します。

## アジャイル、AI、自動化、アナリティクス

### アジャイル

仕事の副産物として証拠を生み出し、監査人を早期に対話に招きます。注意点は、監査の所見の目標が、誠実な自己申告を妨げうることです。

### AI

AI関連の義務は変化しているので、自分に適用される法律を法律顧問と確認し、証拠としてAIシステムの棚卸しを保ちます。AIツールにコンプライアンスの主張を述べさせないでください。注意点は、AIが生成した証拠の要約は、人が元の情報源に照らして検証する必要があることです。

### 自動化

パイプラインとツールからの証拠の収集を自動化し、証拠の自動化率と対応時間を測ります。注意点は、自動化は完全だが間違った証拠を生みうるため、抽出することです。

### アナリティクス

繰り返される所見とクローズ時間を、件数とともに報告します。これが情報を与える判断は、統制がどこで繰り返し失敗するかです。注意点は、監査の労力はコストであり目標ではなく、それを減らすことで網羅率を減らすべきではないことです。

## 業種別の視点

**スタートアップ。** 義務は、大口の顧客や資金調達とともに突然到来しうるものです。習慣を早く築きます。パイプラインにピアレビュー、変更の記録、アクセス統制を持ち、求められたときに証拠が存在するようにします。事業が必要とするときに枠組みを一つ選び、すでに行っていることに対応づけます。

**中小企業。** コンプライアンスの義務は、契約と法律で固定されていることが多く、資源は限られています。義務の短い一覧を保ち、独自の保証レポートを持つマネージドサービスに頼り、単純な証拠のフォルダを保ちます。対処するリスクより高くつくコンプライアンスのツールの購入には注意します。

**大企業。** 多くの義務が重なるので、一つの統制を多くの義務に対応づける統一された統制の枠組みが、大きな労力を節約します。共通の証拠の情報源、共有の所見の追跡、繰り返される依頼を避ける監査のカレンダーを使います。チームが同じことで三回検査されないよう、内部監査、コンプライアンス、セキュリティを調整します。

**政府・公共部門。** コンプライアンスの義務は、調達、記録、アクセシビリティ、データ保護の規則を含め、広範で公的で、国の機関による監査があります。判断と証拠を必要な期間文書化し、可能なところでは機関間でレポートを一貫させ、独立した監査と管理の間に明確な線を保ちます。義務は、選挙や立法とともに変わるかもしれません（トピック 8.5「規制対応・行政向け報告」を参照）。

## ビジネスケース：動機、ROI、TCO

コストには、統制の台帳のツール、証拠のためのパイプラインの連携、アイデンティティとログのシステム、コンプライアンスのスタッフとチームの時間が含まれます。証拠の自動化の初期の労力は大きく、繰り返される手作業の仕事に置き換わります。

見返りは、繰り返される監査の労力の低下、依頼へのより速い応答、繰り返される所見の減少、統制の健全性のより誠実な見方です。また、認証の周期の遅くでの驚きのコストの回避も含まれます。自分たち自身の数字からケースを築きます。前後の監査の準備時間、証拠の対応時間、所見の数と年齢、商談での監査関連の遅れのコスト。方法と関連性をたどれない限り、コンプライアンスのコストの研究の引用は避けます。プログラムのコストと、弱い統制を過度に自動化するリスクを数えます。より広い財務的な扱いは、前の部の最後のトピックにあります（トピック 7.7「投資対効果とビジネスケース」を参照）。

## アンチパターンと落とし穴

- **最後の月に監査の準備をする。** 再構成された証拠と慌てを生む。仕事が行われるときに証拠を記録する。
- **証拠としてのスクリーンショット。** 手作業で、改ざんしやすく、高コストである。システムが生成した記録を使う。
- **所見ゼロを狙う。** 狭い範囲と隠れた問題を報いる。クローズ、繰り返し、網羅率を追跡する。
- **主張によって所見をクローズする。** 同じ所見が戻る。クローズを独立して検証する。
- **監査人を敵対者として扱う。** 双方のコストを増やす。独立性を保ちながら、証拠の設計で協働する。
- **どの義務にも役立たない統制。** 労力がかかり、冷笑を生む。廃止する。
- **悪い統制を自動化する。** 弱い統制の証拠を大規模に生み出す。まず統制をテストする。
- **手作業の職務分掌。** 記憶に頼る。ツールで強制し、例外をレビューする。

## チェックリスト

- [ ] 適用される義務が、オーナーとともに平易な言葉で列挙されている。
- [ ] 各義務が統制と証拠の情報源に対応づけられている。
- [ ] 本番の変更が、リンクされた依頼、レビュー、テスト、デプロイの証拠を自動で伴う。
- [ ] ポリシーの確認が、パイプラインでレビューと職務分掌を強制している。
- [ ] 監査証跡が改ざんに強く、必要な期間保持されている。
- [ ] 証拠の索引があり、依頼の対応時間が測定されている。
- [ ] 独立性を保ちながら、証拠の設計について監査人に相談している。
- [ ] 所見が問題レコードとして記録され、独立した検証でクローズされている。
- [ ] 繰り返される所見が前身にリンクされ、原因が調べられている。
- [ ] 監査の労力が傾向として追跡され、重複についてレビューされている。

## AIプロンプト

**義務を統制に対応づける。**

```text
以下は [業種と法域] の私たちのサービスに適用される義務の一覧です：[平易な言葉で貼り付け]。以下は私たちの統制の一覧です：[貼り付け]。各義務を、統制、各統制が運用されていることを示す証拠、オーナーの役割に対応づける表を作ってください。統制のない義務、義務のない統制、弱い証拠に印を付けてください。法的な結論を出さないでください。前提と、法務とコンプライアンスへの問いを列挙してください。
```

**証拠の自動化を計画する。**

```text
私たちの手作業の監査の証拠には次があります：[費やした時間付きのアイテムの一覧]。記録システムは：[ツールの一覧]。証拠のアイテムを労力とリスクで順位付け、それぞれを記録システムからどう自動で収集できるか、何が証拠を信頼できるものにするか（改ざん耐性、完全性）、監査人と何を確認すべきかを提案してください。特定のツールの機能を仮定しないでください。前提を列挙してください。
```

**繰り返される所見を分析する。**

```text
以下は、直近の [数] 回の監査周期の所見で、原因と修正を伴います：[無害化して貼り付け]。所見を根本的な原因でグループ化し、繰り返しを特定し、以前の修正がなぜ保たれなかったかを示唆してください。原因による所見の照合の規則と、クローズの検証のステップを提案してください。与えられた情報を超えて推測しないでください。前提を列挙してください。
```

**監査人との早期の対話を準備する。**

```text
[統制またはプロセス] の証拠の作り方を変えることについての、内部監査との会議の議題を起案してください。変更する計画、答えが必要な問い（許容される証拠、サンプリング、重要性）、独立性を保つために彼らに求めないこと、結果をどう記録するかを含めてください。平易な言葉を使ってください。前提とリスクを列挙してください。
```

## AIスキル

- [サービスマネジメントメトリクスのスキル](../../../../skills/service-management-metrics-skill/SKILL.md)：コンプライアンスまたは監査のメトリクスの、組になる防護柵を探すときに使います。
- [サービスマネジメントメトリクスのメンテナースキル](../../../../skills/service-management-metrics-maintainer-skill/SKILL.md)：コンプライアンスのメトリクスの項目が、悪用の手口、防護柵、独立性の規則を備えているかを確認するときに使います。

## 要点

- デリバリーの副産物として、パイプラインと記録システムから証拠を生み出し、どれだけが自動かを測る。
- すべての義務を、統制、オーナー、証拠の情報源に対応づける。
- 証拠の設計に監査人を早く招き、彼らの独立性を守る。
- 原因を取り除いて所見をクローズし、クローズを独立して検証し、繰り返される所見の率を見る。
- 所見ゼロなどの目標を避け、成果とともに労力を追跡する。
- ツールで職務分掌を強制し、監査証跡を改ざんに強く保つ。
