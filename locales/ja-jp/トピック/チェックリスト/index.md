# チェックリスト

プログラムのチームのための三つのチェックリスト：一つはメトリクス一つのレビュー、一つはダッシュボードの立ち上げ、一つはメトリクスプログラムの監査です。記入して保管する書式としてではなく、チームとの対話の促しとして使ってください。調整し、自分たちの文脈に合わない項目は落としてください。

## メトリクスのレビューのチェックリスト

メトリクスが採用される前と、各定期レビューで使います（トピック 1.4「メトリクスのガバナンスとオーナーシップ」を参照）。

**目的**

- [ ] メトリクスが、名前の挙がった聞き手が尋ねた問いに答える。
- [ ] それが情報を与えるべき判断が書き下されている。
- [ ] 成果を測るか、成果と明確に組になっている（トピック 1.3「アウトプットよりアウトカム：何を測るかを選ぶ」を参照）。

**定義**

- [ ] 書面の定義、計算式、単位、データソースがある。
- [ ] 時計や境界の規則が明示されている（数え始め、止まり、一時停止するとき）。
- [ ] オーナーと、数字がおかしく見えるときに尋ねる人が指名されている。
- [ ] ギャップや入力の仕方の変化を含め、データの既知の限界が記録されている。

**誠実さ**

- [ ] 最も起こりやすい悪用の手口が書き下されている。
- [ ] 組になる防護柵のメトリクスまたはプラクティスがある。
- [ ] メトリクスはチーム、サービス、システムを記述し、個人を決してランク付けしない。
- [ ] 時間の測定値が、中央値と高いパーセンタイルを標本サイズとともに示している（トピック 1.6「サービスメトリクスのための統計リテラシー」を参照）。
- [ ] 通常の変動に照らして変化を読めるよう、複数の期間のベースラインがある。

**利用**

- [ ] 仕事をするチームが、その数字を最初に見て、定義を手伝った。
- [ ] 前回のレビューが、待つという判断を含め、記録された判断につながった。
- [ ] メトリクスを廃止する条件が書き下されている。

## ダッシュボード立ち上げのチェックリスト

ダッシュボードを聞き手に示す前に使います（トピック 11.1「サービスメトリクスのダッシュボード設計」を参照）。

**聞き手と内容**

- [ ] 聞き手とその問いが書き下され、聞き手がスケッチのレビューを手伝った。
- [ ] 見方にはおおよそ九以下の測定値があり、詳細は一段下にある。
- [ ] 集合が、フロー、品質、信頼性、体験、コストにわたってバランスしている。
- [ ] すべての測定値に、起こりやすい歪みから守る相棒がある。

**明確さ**

- [ ] すべての値が傾向と文脈を示し、イベントが注記されている。
- [ ] すべての測定値に、定義、情報源、オーナー、更新時刻、既知のギャップが1クリック以内にある。
- [ ] 目標が参照として示され、状態の色は変動を考慮した述べられた規則に従っている。
- [ ] 情報を加えない装飾が取り除かれている。

**信頼と運用**

- [ ] 憲章に合意し、個人レベルの見方がオフになっている（トピック 11.3「恐れを生まずにメトリクスを展開する」を参照）。
- [ ] チームが自分たちのデータを見て、訂正する時間があった。
- [ ] データが自動で引かれ、鮮度の確認と情報源との突合がある（トピック 11.2「ツールの全体像」を参照）。
- [ ] 名前の挙がったオーナー、レビューの日付、異議の経路がある。
- [ ] このダッシュボードが置き換えるレポートに、廃止の日付がある。

## プログラム監査のチェックリスト

年2回、チームとともに、自己評価と並べて使います（トピック 12.5「成熟度の自己評価」を参照）。

**目的と信頼**

- [ ] プログラムにスポンサーと、リーダーが従う書面の憲章がある。
- [ ] 報告された憲章の違反が対処され、結果が名前なしで公表された。
- [ ] チームのアンケートとヒヤリハットの報告が、上昇する恐れを示唆していない。
- [ ] 組織のツールやスライドのどこにも、チームや個人のランキング表がない。

**測定値とデータ**

- [ ] 各チームが、先四半期に自分たちの測定値が情報を与えた判断を挙げられる。
- [ ] 定義が、オーナー付きの、持ち運べるカタログに保たれている。
- [ ] 情報源の網羅、パイプラインの信頼性、突合が確認され、見えている。
- [ ] 定義と履歴のエクスポートが、昨年中にテストされた。

**バランスと幅**

- [ ] 各見方で、成果の測定値が活動の測定値の隣にある。
- [ ] AI関連の測定値が、量だけでなく、ベースライン、抽出、検証された成果に従っている（トピック 10.4「メトリクスのインフレと品質の希薄化」を参照）。
- [ ] 自動化とパイプラインの測定値に、失敗、ロールバック、迂回が含まれ、各自動化にオーナーがいる（トピック 10.6「自動化とオーケストレーションのメトリクス」とトピック 10.7「パイプラインと自動化された変更のメトリクス」を参照）。
- [ ] データ品質と不確実性が数字の隣に示され、ITIL 5の主張が検証済みまたは未確認とラベル付けされている（トピック 10.8「アナリティクスとデータ品質のメトリクス」とトピック 1.8「ITIL 5の測定と価値の成果」を参照）。
- [ ] コスト、リスク、人の測定値が重要なところにあり、どれも個人をランク付けするために使われていない。

**改善**

- [ ] 前回のレビューの改善アクションが、完了した、または理由を添えて落とされた。
- [ ] 昨年中に測定値とレポートが廃止された。
- [ ] 測定のためにチームに求める労力が見積もられ、彼らにとって許容できる。
- [ ] プログラム自体がチームとレビューされ、その結果計画が変わった（トピック 11.5「段階的な導入ロードマップ」を参照）。
