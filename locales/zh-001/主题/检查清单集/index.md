# 检查清单集

为计划团队准备的三份检查清单：一份用于评审单项测量值，一份用于仪表盘上线，一份用于审计度量计划。把它们当作与团队交谈的提示，而不是要填写并归档的表格。请加以调整，并删去不适合你背景的条目。

## 度量评审检查清单

在采用某项测量值之前，以及每次定期评审时使用（见主题 1.4，度量治理与归属）。

**目的**

- [ ] 该测量值回答了指名的受众所问的问题。
- [ ] 它应当为之提供依据的决定已写下。
- [ ] 它度量成果，或者明确地与一项成果配对（见主题 1.3，结果重于产出：选择度量什么）。

**定义**

- [ ] 存在书面的定义、公式、单位和数据来源。
- [ ] 时钟或边界规则是明确的（何时开始、停止和暂停计数）。
- [ ] 指名了负责人，以及数字看起来有误时可以询问的人。
- [ ] 记录了数据的已知局限，包括缺口和录入方式的变化。

**诚实**

- [ ] 写下了最可能的钻空子途径。
- [ ] 已有配对的护栏测量值或实践。
- [ ] 该测量值描述团队、服务或系统，绝不给个人排名。
- [ ] 时间测量值展示中位数和高百分位数，并附样本量（见主题 1.6，服务度量的统计素养）。
- [ ] 存在若干期的基线，使变化可以对照普通的变异来解读。

**使用**

- [ ] 做这项工作的团队先看到数字，并帮助定义了它。
- [ ] 上一次评审引向了被记录的决定，包括等待的决定。
- [ ] 写下了淘汰该测量值的条件。

## 仪表盘上线检查清单

在仪表盘向其受众展示之前使用（见主题 11.1，设计服务度量仪表盘）。

**受众与内容**

- [ ] 写下了受众及其问题，并且受众帮助评审了草图。
- [ ] 视图的测量值不超过约九项，细节放在下一层。
- [ ] 该集合在流动、质量、可靠性、体验和成本之间保持平衡。
- [ ] 每项测量值都有防范其可能扭曲的配对测量值。

**清晰**

- [ ] 每个值都展示趋势和背景，并注明事件。
- [ ] 每项测量值的定义、来源、负责人、刷新时间和已知缺口，都只需点击一下。
- [ ] 目标作为参照展示，任何状态颜色都遵循考虑变异的所述规则。
- [ ] 已移除不增加信息的装饰。

**信任与运行**

- [ ] 已商定章程，个人层面的视图已关闭（见主题 11.3，推行度量而不滋生恐惧）。
- [ ] 团队已看到自己的数据，并有时间更正。
- [ ] 数据自动拉取，附新鲜度检查和与来源的对账（见主题 11.2，工具全景）。
- [ ] 存在指名的负责人、评审日期和质疑路径。
- [ ] 该仪表盘所取代的报告有淘汰日期。

## 计划审计检查清单

每年两次，与团队一起，配合自我评估使用（见主题 12.5，成熟度自评）。

**目的与信任**

- [ ] 计划有赞助者和领导者所遵守的书面章程。
- [ ] 所报告的对章程的违反已被处理，并在不点名的情况下公布了结果。
- [ ] 团队调查和未遂事件的报告没有显示恐惧在上升。
- [ ] 在组织的工具或幻灯片的任何地方，都不存在团队或个人的排行榜。

**测量值与数据**

- [ ] 每个团队都能指出上一个季度其测量值为之提供依据的决定。
- [ ] 定义保存在可移植的目录中，并有负责人。
- [ ] 检查并展示来源覆盖、流水线可靠性和对账。
- [ ] 过去一年里，测试过定义和历史的导出。

**平衡与广度**

- [ ] 在每个视图中，成果测量值与活动测量值并列。
- [ ] 与 AI 相关的测量值遵循基线、抽样和经验证的成果，而不只是数量（见主题 10.4，度量膨胀与质量稀释）。
- [ ] 自动化和流水线的测量值包括失败、回退和绕开，并且每项自动化都有负责人（见主题 10.6，自动化与编排度量，以及主题 10.7，流水线与自动化变更度量）。
- [ ] 数据质量和不确定性展示在数字旁边，并且 ITIL 5 的声称被标注为已验证或未经确认（见主题 10.8，分析与数据质量度量，以及主题 1.8，ITIL 5 度量与价值成果）。
- [ ] 在重要之处有成本、风险和人员的测量值，并且没有一项被用来给个人排名。

**改进**

- [ ] 上一次评审的改进行动已完成，或附理由放弃。
- [ ] 过去一年里淘汰了测量值和报告。
- [ ] 已估计计划对团队在度量上所要求的工作量，并且团队可以接受。
- [ ] 已与团队一起评审计划本身，并且计划因此而改变（见主题 11.5，渐进式采纳路线图）。
